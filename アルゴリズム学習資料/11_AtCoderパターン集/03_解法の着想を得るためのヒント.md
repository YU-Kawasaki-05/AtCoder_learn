# 解法の着想を得るためのヒント

競技プログラミングの難しい点の一つは、問題を見たときに「どのようなアルゴリズムやデータ構造を使うべきか」という着想を得ることです。このドキュメントでは、問題を見たときに解法の糸口をつかむためのヒントを紹介します。

## 1. 制約から解法を推測する

問題文に書かれている制約（入力サイズや実行時間制限）から、使うべきアルゴリズムを推測できることがあります。

| 入力サイズ N | 許容される時間計算量 | 可能なアルゴリズム |
|------------|-------------------|-----------------|
| N ≤ 10     | O(N!)、O(2^N)     | 全列挙、ビット全探索、再帰関数 |
| N ≤ 20     | O(2^N)            | ビット全探索、半分全列挙 |
| N ≤ 100    | O(N^3)            | 三重ループ、ワーシャルフロイド法 |
| N ≤ 1,000  | O(N^2)            | 二重ループ、二次元DP |
| N ≤ 10,000 | O(N√N)、O(N log^2 N) | 素因数分解、セグメント木の複雑な操作 |
| N ≤ 100,000 | O(N log N)        | ソート、二分探索、ヒープ、セグメント木 |
| N ≤ 1,000,000 | O(N)           | 一重ループ、累積和、ハッシュ、Union-Find |
| N ≤ 10^9   | O(log N)          | 二分探索、数学的解法 |

## 2. 問題のパターンを見極める

問題文の特徴から、よくあるパターンを見つけ出すことができます。

### 2.1 「最小」「最大」「最適」という言葉がある
→ 動的計画法、貪欲法、二分探索が使えるかもしれない

### 2.2 グラフや経路に関する言葉がある
→ DFS/BFS、ダイクストラ法、最小全域木などのグラフアルゴリズム

### 2.3 「区間」「部分列」「連続する～」という言葉がある
→ 累積和、セグメント木、尺取法、imos法

### 2.4 「組み合わせ」「場合の数」という言葉がある
→ 動的計画法、数学的解法、組み合わせ論

### 2.5 「すべての可能性」「全ての組み合わせ」という言葉がある
→ 全探索、ビット全探索、バックトラック

## 3. 小さな例で考える

問題文に与えられている例や、自分で小さな例を作って解いてみることで、パターンを見つけられることがあります。

1. 具体例を手で解いてみる
2. その過程で使った判断や計算を一般化できないか考える
3. パターンや規則性がないか探す

## 4. 問題を単純化する

複雑な問題は、単純な部分問題に分解して考えると解法が見えてくることがあります。

1. 制約を単純化する（例：二次元→一次元）
2. 特殊なケースから考える
3. 似た問題を思い出す

## 5. 逆向きに考える

ゴールから逆算して考えると解法が見つかることがあります。

1. 答えを仮定して、その条件を満たすか検証する
2. 最終状態から初期状態に戻る道筋を考える

## 6. 二分探索で判定問題に変換する

「最小値を求めよ」「最大値を求めよ」という最適化問題は、「X以下/以上で条件を満たすか？」という判定問題に変換できることがあります。

```python
def is_valid(x):
    # xが条件を満たすかどうかを判定
    pass

# 最小値を求める二分探索
left, right = 最小値, 最大値
while right - left > 1:
    mid = (left + right) // 2
    if is_valid(mid):
        right = mid  # 条件を満たすならより小さい値を探す
    else:
        left = mid   # 条件を満たさないならより大きい値を探す
# rightが答え
```

## 7. 解法が思いつかないときの対処法

1. 問題文をもう一度注意深く読み、見落としがないか確認する
2. 極端なケースを考える（N=1, N=2, 全て同じ値など）
3. 別の視点で問題を言い換えてみる
4. 図を描いて視覚化する
5. 既知のアルゴリズムが適用できないか考える
6. 一度離れて別の問題に取り組み、後で戻ってくる

## 8. アルゴリズムごとの特徴的なキーワード

各アルゴリズムに特徴的なキーワードを知っておくと、問題文からヒントを得られることがあります。

### 動的計画法（DP）
- 「最適な」「最大の」「最小の」
- 「部分問題」「部分構造」
- 「場合の数」「パターン」

### 二分探索
- 「k番目の」「最小の～なもの」
- 「可能かどうか判定せよ」

### 幅優先探索（BFS）
- 「最短経路」「最小手数」
- 「迷路」「グリッド」

### 深さ優先探索（DFS）
- 「連結成分」「閉路」
- 「すべての経路」

### 貪欲法
- 「最大化」「最小化」
- 「可能な限り多く」

### 累積和
- 「区間の和」「部分列の和」
- 「連続する」

## 9. 発想の転換例

よくある発想の転換パターンをいくつか紹介します。

1. **包除原理**: 「条件を満たすものを数える」→「全体から条件を満たさないものを引く」
2. **二部グラフ**: 「2色で塗り分けられるか」→「二部グラフ判定」
3. **逆元**: 「割り算のmodを求める」→「逆元を使う」
4. **座標圧縮**: 「値が大きすぎる」→「相対的な大小関係だけ保持」
5. **反転**: 「最小化」→「最大化の否定」

## 10. 最後に

解法の着想を得る能力は、経験を積むことで向上します。多くの問題を解き、解説を読むことで、パターンを認識する力が身につきます。また、一つの問題に複数のアプローチがあることも多いため、柔軟な思考を心がけましょう。

何より大切なのは、「この問題はどのカテゴリに属するか」と常に考える習慣をつけることです。それにより、過去の経験を新しい問題に応用できるようになります。
